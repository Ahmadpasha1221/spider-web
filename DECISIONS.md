# Phase 0 Decisions

These decisions close the product and format questions that can be answered before implementation. Provider format facts remain evidence-bounded; unresolved research is tracked separately in `docs/agents/`.

| Topic                    | Decision for 0.1                                                                                                                                                                                                                                                                                                                                                                                                                   | Reason / consequence                                                                                                                                                                                                                                                                                             |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Runtime                  | TypeScript on Node.js; one package, no monorepo yet                                                                                                                                                                                                                                                                                                                                                                                | CLI distribution is the primary goal; avoid premature package boundaries.                                                                                                                                                                                                                                        |
| Toolchain                | ESM, Node.js >=22, TypeScript `tsc` build, Node `util.parseArgs` CLI parser, ESLint flat config with `typescript-eslint`, Prettier, Vitest                                                                                                                                                                                                                                                                                         | Small command surface does not justify a runtime CLI framework; standard tools keep contributor workflow familiar. Exact dev dependency versions are pinned when Phase 1 begins.                                                                                                                                 |
| Schema validation        | JSON Schema 2020-12 is the source of truth; Ajv validator with strict schema checks and `ajv-formats`. Generate TypeScript declarations from schemas using `json-schema-to-typescript`.                                                                                                                                                                                                                                            | Avoid duplicate hand-maintained model types and runtime rules; cross-record invariants still require semantic validation.                                                                                                                                                                                        |
| Format/runtime libraries | `ajv` + `ajv-formats` for validation, `json-schema-to-typescript` for generated types, `jsonc-parser` for strict JSON syntax/tree checks, [`canonicalize`](https://www.rfc-editor.org/rfc/rfc8785.html#appendix-G) for RFC 8785, [`yazl`](https://github.com/thejoshwolfe/yazl) for Egg writing, and [`yauzl`](https://github.com/thejoshwolfe/yauzl) for Egg reading; Node `crypto` for SHA-256                                   | Reuse reviewed format/security implementations rather than writing JCS or ZIP internals. Lock exact versions and require deterministic ZIP fixture checks before enabling export. `yazl` exposes fixed mtime/mode and `forceDosTimestamp`; `yauzl` supports strict filename validation and declared-size checks. |
| Executable               | `spider-web`                                                                                                                                                                                                                                                                                                                                                                                                                       | Clear relation to the project and avoids a generic `spider` command collision. npm package availability remains unverified, so publishing is blocked until the registry can be checked.                                                                                                                          |
| Session identity         | `spw_` + UUID v4. Native agent session IDs are adapter metadata, never a core field.                                                                                                                                                                                                                                                                                                                                               | Available in Node core, random without centralized allocation, and no timestamps required for uniqueness.                                                                                                                                                                                                        |
| Canonical state          | One `session.json` carries all captured neutral data, including full available conversation and normalized tool events                                                                                                                                                                                                                                                                                                             | Avoid split files that can disagree. `handoff.md` is a derived compact view.                                                                                                                                                                                                                                     |
| File facts               | `files` records attribution/evidence (created/modified/deleted); `git.files` records a point-in-time Git status (staged/unstaged/untracked/deleted)                                                                                                                                                                                                                                                                                | A transcript claim and present worktree status answer different questions. Never infer one from the other.                                                                                                                                                                                                       |
| Event linkage/order      | Messages, tool calls/results, commands, tests, and errors have unique session-local event IDs and a monotonically increasing `sequence`; tool results also link by `tool_call_id`.                                                                                                                                                                                                                                                 | Preserves order when source timestamps are missing or ambiguous and avoids provider-shaped fields.                                                                                                                                                                                                               |
| Event IDs                | Lowercase `e` plus base-36 sequence (e.g. `e1`, `e2`); tool results reference the tool call ID separately.                                                                                                                                                                                                                                                                                                                         | IDs are stable within one Spider Session and sortable without provider ID leakage.                                                                                                                                                                                                                               |
| Provenance               | `evidence.source` plus `confidence`; claims without evidence are not invented                                                                                                                                                                                                                                                                                                                                                      | Makes transcript-derived versus observed worktree facts distinguishable.                                                                                                                                                                                                                                         |
| Environment              | Allowlist OS family/version, runtime name/version, and shell executable name; no environment variables or user/home values                                                                                                                                                                                                                                                                                                         | Useful portability context without copying secrets or account identifiers.                                                                                                                                                                                                                                       |
| Project path             | Absolute root path lives only in the local repository index. Portable session stores project name and optional relative root hint.                                                                                                                                                                                                                                                                                                 | Prevents routine Egg export from leaking local usernames and directories.                                                                                                                                                                                                                                        |
| Portable paths           | All `files`, `git.files`, artifact source paths, and Egg entry paths use relative POSIX paths. Paths outside project root have no portable path; store content only after explicit selection.                                                                                                                                                                                                                                      | Prevents drive/UNC paths and traversal from entering a portable Egg.                                                                                                                                                                                                                                             |
| Local storage            | Linux: `$XDG_DATA_HOME/spider-web`, fallback `~/.local/share/spider-web`; macOS: `~/Library/Application Support/spider-web`; Windows: `%LOCALAPPDATA%\Spider Web` (platform APIs/environment, not hardcoded profile paths). Config uses platform config convention.                                                                                                                                                                | Predictable platform-native location. In-memory path helper is needed before persistence code.                                                                                                                                                                                                                   |
| Egg container            | `.spider-egg` is an uncompressed ZIP with UTF-8 `manifest.json`, `session.json`, deterministic `handoff.md`, and explicitly selected content-addressed artifacts                                                                                                                                                                                                                                                                   | Standard inspectable tooling and broad portability. Uncompressed ZIP avoids compressor-version output variation; Eggs may be larger.                                                                                                                                                                             |
| Egg determinism          | Canonical JSON (RFC 8785/JCS), LF text, lexicographically sorted entries, ZIP timestamp fixed at 1980-01-01 00:00:00, regular-file mode 0644, ZIP_STORED, no generated build timestamp/producer in hashed contents                                                                                                                                                                                                                 | Same normalized session and same selected artifacts produce byte-identical Egg across platforms. Manifest does not hash itself; it hashes every other entry.                                                                                                                                                     |
| Egg safety               | Reject absolute/traversal/duplicate paths, symlinks, encrypted/unsupported entries, compression methods other than STORED, non-canonical metadata, entry-count and expanded-size limit breaches, bad checksums, unknown required features, and unsupported versions. Phase 2 reads and validates entries in memory without extracting them; any future extraction API must use a new empty destination and explicit caller action. | Prevents path traversal and common archive abuse. Initial limits: 2,000 files and 256 MiB expanded total; configurable only downward in 0.1.                                                                                                                                                                     |
| Handoff                  | Deterministic, no model-generated summarization. State first; include only messages marked `handoff_relevant`, newest-first, with a hard 12,000-Unicode-character total output cap and deterministic truncation notices.                                                                                                                                                                                                           | Compact and predictable without hidden network/AI calls. Full conversation remains in `session.json`.                                                                                                                                                                                                            |
| Handoff relevance        | Adapters mark the newest user request and the latest assistant response; they may additionally mark explicit decision, failure, or blocker exchanges using documented deterministic rules. User may edit these flags.                                                                                                                                                                                                              | Makes the compact conversation useful while avoiding an AI summarization dependency.                                                                                                                                                                                                                             |
| Continue                 | `session continue` only prepares/prints the selected adapter's declared instructions and handoff file. It does not launch an agent, alter provider storage, or claim native resume by default.                                                                                                                                                                                                                                     | Safe Level 3 baseline and explicit user control.                                                                                                                                                                                                                                                                 |
| Secret policy            | No automatic project scan/attachment. `.env`, key/credential files, binaries, and files over 5 MiB are excluded from default artifact selection. User-selected inclusions get a path/size preview.                                                                                                                                                                                                                                 | Minimize accidental disclosure; selected files still require review.                                                                                                                                                                                                                                             |
| Export confirmation      | Preview session/conversation presence and artifact names/sizes. Require interactive confirmation for conversations/artifacts; in non-interactive mode require `--confirm-sensitive`.                                                                                                                                                                                                                                               | An Egg can expose sensitive transcript or code contents. Preview omits actual text.                                                                                                                                                                                                                              |
| Schema version           | Phase 1 supports exactly Spider Session `1.0` and Egg `0.1`. Reject all unsupported versions. Reject unknown core fields; preserve provider data only inside `extensions`.                                                                                                                                                                                                                                                         | Version support is explicit and testable. A later schema version must ship its schema before readers accept it.                                                                                                                                                                                                  |
| Manifest limits          | Manifest JSON is limited to 1 MiB; at most 2,000 total Egg entries including the manifest and 256 MiB expanded payload bytes. Required feature list is empty in Egg 0.1.                                                                                                                                                                                                                                                           | Enforces limits before archive code exists and prevents unbounded package metadata.                                                                                                                                                                                                                              |

## Still external / not design blockers

- Whether npm name `spider-web` is publishable. Registry access failed in this environment; do not publish until checked.
- Whether any agent's private local database/JSONL is a supported contract. Until documented, direct parsing stays experimental or disabled.
- Exact adapter mappings, validated against sanitized real fixtures. These can add extension fields, but changes to core semantics require protocol review.
